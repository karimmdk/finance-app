# اپلیکیشن مدیریت مالی شخصی — نسخه Python (پرتابل)

این نسخه بازنویسی کامل بک‌اند از Node.js/Express به **Python (FastAPI)** است، دقیقاً به همان
دلیلی که خواسته شد: امکان ساخت یک بسته تک‌پوشه‌ای که با کپی‌کردن روی هر سیستمی (بدون نصب
Python، بدون npm/node، بدون هیچ وابستگی) مستقیم قابل اجراست.

فرانت‌اند (React) **بدون هیچ تغییری** از پروژه Node اصلی استفاده می‌شود — فقط build شده و در
پوشه `static/` قرار می‌گیرد؛ چون این بک‌اند دقیقاً همان API (همان مسیرها، همان فرمت JSON) را
ارائه می‌دهد.

## چرا Python برای این هدف مناسب‌تر بود
- `sqlite3` بخشی از کتابخانه استاندارد پایتون است — بر خلاف `better-sqlite3` در Node که یک
  ماژول native (کامپایل‌شده مخصوص هر سیستم‌عامل) است و بسته‌بندی تک‌فایلی را با ابزارهایی مثل
  `pkg` بسیار شکننده می‌کند.
- همین موضوع باعث شد PyInstaller بتواند یک بسته کاملاً پرتابل و **تست‌شده** بسازد — نسخه لینوکسی
  با یک `PATH` کاملاً خالی از پایتون اجرا و تأیید شد (به بخش «تست انجام‌شده» پایین مراجعه کنید).

## ساختار پروژه
```
app/
  db.py              اتصال SQLite + اجرای migration (schema_migrations tracking)
  main.py            ساخت FastAPI app (create_app) — قابل تست بدون باز کردن پورت واقعی
  schemas.py         مدل‌های Pydantic (معادل Zod در نسخه Node)
  deps.py            Dependency Injection برای دسترسی به DB
  lib/               منطق مالی deterministic — دقیقاً معادل src/lib/*.ts نسخه Node
  importers/         پارسر Excel بانکی + orchestration ایمپورت
  routes/            روت‌های FastAPI — دقیقاً معادل src/server/routes/*.ts
migrations/          همان فایل‌های SQL خام نسخه Node (بدون تغییر، قابل استفاده مستقیم)
static/              فایل‌های build‌شده React (بعد از اجرای build.sh پر می‌شود)
tests/               ۶۴ تست pytest — شامل رگرسیون‌های واقعی پیدا‌شده حین توسعه
run.py               نقطه ورود اصلی (اجرای مستقیم یا داخل بسته PyInstaller)
build.sh             ساخت بسته پرتابل لینوکس/مک
build_windows.bat    ساخت بسته پرتابل ویندوز (باید روی خودِ ویندوز اجرا شود)
```

## اجرا در حالت توسعه
```bash
pip install -r requirements.txt
python3 run.py          # روی http://localhost:4000 بالا می‌آید (هم API هم فرانت‌اند build‌شده)
```
اگر `static/` خالی است، ابتدا فرانت‌اند React را از پروژه Node بیلد و کپی کنید:
```bash
cd ../finance-app && npm run build
cp -r dist-ui/* ../finance-app-py/static/
```

## تست
```bash
python3 -m pytest tests/ -v
```

## ساخت بسته پرتابل (تک‌پوشه‌ای، بدون نیاز به نصب Python روی مقصد)

### لینوکس/مک
```bash
./build.sh
```
خروجی در `dist/finance-app/` — همین پوشه را هرجا کپی کنید، بعد `./finance-app` را اجرا کنید.

### ویندوز
PyInstaller نمی‌تواند از لینوکس/مک یک فایل exe واقعی برای ویندوز بسازد (نیاز به build واقعی
روی ویندوز دارد). **این بخش را خودتان روی یک سیستم ویندوز اجرا کنید** (فقط برای مرحله ساخت،
پایتون لازم است؛ نتیجه نهایی برای اجرا نیازی به پایتون ندارد):
```cmd
build_windows.bat
```
خروجی در `dist\finance-app\` — همین پوشه را هرجا کپی کنید، `finance-app.exe` را دوبار کلیک کنید.

> چرا من (Claude) نتوانستم خودم فایل exe ویندوز را بسازم؟ چون محیط من لینوکسی است و
> PyInstaller باید روی خودِ سیستم‌عامل مقصد اجرا شود تا باینری واقعاً روی آن سیستم کار کند —
> ساختن یک exe ویندوزی بدون داشتن ویندوز برای تستش، غیرقابل‌اعتماد است و ترجیح دادم چیزی
> تحویل ندهم که تست‌نشده باشد.

## تست انجام‌شده روی بسته پرتابل لینوکس
- بسته کامل به یک مسیر کاملاً متفاوت کپی شد (شبیه‌سازی «کپی‌پیست به سیستم دیگر»)
- با `PATH` خالی از هر گونه پایتون اجرا شد و **کار کرد** — یعنی هیچ وابستگی پنهانی به Python
  نصب‌شده روی سیستم ندارد
- تمام گردش‌کار اصلی تست شد: ساخت حساب، ثبت تراکنش با استخراج خودکار از description، ایمپورت
  واقعی فایل بانکی (۳ تراکنش، شامل ردیف اصلاح سند)، و پایدار ماندن داده کنار خودِ فایل اجرایی
  (نه داخل پوشه موقت) — یعنی اگر کل پوشه را جابه‌جا کنید، داده‌هایتان هم همراهش می‌آید.

## نکات فنی مهم (باگ‌های واقعی پیدا و رفع‌شده حین این بازنویسی)
1. **Trailing slash redirect**: مسیرهایی که با `("/")` تعریف شده بودند (مثل `@router.get("/")`
   زیر prefix `/api/accounts`) باعث می‌شدند FastAPI به‌طور خودکار به `/api/accounts/` ریدایرکت
   (307) کند. فرانت‌اند/curl بدون دنبال‌کردن ریدایرکت این را به‌عنوان شکست می‌دید. راه‌حل: همه
   این مسیرها به `("")` تغییر کردند. تست pytest با `follow_redirects=False` این را قفل می‌کند.
2. **فرمت خطا**: FastAPI پیش‌فرض خطاها را با کلید `"detail"` برمی‌گرداند، ولی فرانت‌اند React
   (بدون تغییر از نسخه Node) انتظار `"error"` دارد. دو exception handler سفارشی در `app/main.py`
   این را اصلاح می‌کند.
3. **مسیر پایه اشتباه در run.py**: نسخه اولیه یک `.parent` اضافه داشت که باعث می‌شد فایل‌های
   استاتیک/migration در مسیر اشتباه جست‌وجو شوند (404 برای فرانت‌اند). تست رگرسیون در
   `tests/test_run_entrypoint.py` این را پوشش می‌دهد.
4. **camelCase در پاسخ import/preview**: چون `NormalizedTransaction` پایتونی از snake_case
   استفاده می‌کند ولی فرانت‌اند React انتظار camelCase (`transactionDate`) دارد، یک لایه
   سازگاری (`_txn_to_camel`) در `app/routes/transactions.py` این تبدیل را انجام می‌دهد.

همه این‌ها حین توسعه با تست واقعی (نه فرض) پیدا و رفع شدند — جزئیات در پیام‌های commit.

## قوانین خودکار (Rules)

- **همه قوانین فعال بررسی می‌شوند** (نه فقط اولین): برچسب‌ها ادغام می‌شوند؛ اگر چند قانون دسته‌بندی بدهند، قانون جدیدتر (شناسه بزرگ‌تر) بر قوانین پیش‌فرض غالب است.
- **چند مقدار در یک قانون (OR):** با `|` یا `،` یا `؛` یا خط جدید یا «یا» جدا کنید، مثلاً `82000221 | 08975292`.
- **مقایسه هوشمند:** ارقام فارسی/عربی/انگلیسی یکسان‌اند؛ `ي/ك` عربی با `ی/ک` یکی است؛ نیم‌فاصله نادیده گرفته می‌شود. مقدار کاملاً عددی (مثل شماره پایانه) به‌صورت یک عدد کامل تطبیق می‌شود و صفر ابتدایی اختیاری است.
- **اجرا روی تراکنش‌های بدون دسته:** `POST /api/rules/run-on-uncategorized`
- **اعمال مجدد روی همه تراکنش‌ها:** `POST /api/rules/run-on-all` با بدنه‌ی اختیاری `{"overwriteCategory": true|false}` (پیش‌فرض true = دسته‌ی فعلی هم طبق قوانین بازنویسی می‌شود؛ برچسب‌ها همیشه فقط اضافه می‌شوند).
- **بازپردازش توضیحات روی همه تراکنش‌ها:** `POST /api/transactions/reparse-descriptions` با `{"force": true}` (دکمه‌ی UI همین را می‌فرستد).


## خروجی/ورودی CSV (round-trip)

- **خروجی تراکنش‌ها:** `GET /api/backup/transactions.csv` — شامل نام حساب، تاریخ میلادی و شمسی، ساعت،
  نوع، مبلغ، شرح، شماره سند، فیلدهای استخراج‌شده (طرف‌حساب/کارت/شبا/بانک/دلیل)، **دسته‌بندی به‌صورت مسیر
  کامل** (`والد > فرزند`)، شخص، **برچسب‌ها**، یادداشت، استثنا از آنالیز و شناسه انتقال.
- **خروجی دسته‌بندی‌ها و برچسب‌ها:** `GET /api/backup/categories-tags.csv` — همه دسته‌ها (با ساختار
  والد/فرزند) و همه برچسب‌ها، حتی موارد بدون تراکنش، به‌همراه رنگ/آیکن و تعداد استفاده.
- **درون‌ریزی تراکنش‌ها:** همان مسیرهای `POST /api/transactions/import/preview` و `.../commit`؛ اگر فایل
  ارسالی CSV باشد (یا پسوند `.csv` داشته باشد) به‌جای پارسر اکسل بانکی، پارسر CSV اجرا می‌شود. حساب،
  دسته‌بندی، شخص و برچسب ناموجود خودکار ساخته می‌شود. با فیلد فرم `updateExisting` (پیش‌فرض `true`)
  دسته/شخص/برچسبِ تراکنش‌های تکراریِ از قبل موجود هم از روی فایل به‌روزرسانی می‌شود؛ مقدار خالی چیزی را
  پاک نمی‌کند و برچسب‌ها فقط اضافه می‌شوند.
- **درون‌ریزی دسته‌بندی‌ها و برچسب‌ها:** `POST /api/backup/import-categories-tags` — فقط موارد ناموجود را
  می‌سازد و رنگ/آیکن موارد موجود را به‌روز می‌کند؛ چیزی حذف نمی‌شود.
- فرمت‌های قدیمی‌تر (ستون‌های `account_id`/`category_id`/`person_id`) هم تا حد امکان خوانده می‌شوند؛
  جداکننده `,`/`;`/Tab و رمزگذاری UTF-8/UTF-16/cp1256 (اکسل ویندوز فارسی) خودکار تشخیص داده می‌شود.
  جزئیات پیاده‌سازی: `app/lib/csv_exchange.py`.


## فونت (بدون وابستگی به CDN)

فونت Vazirmatn قبلاً از `cdn.jsdelivr.net` بارگذاری می‌شد. حالا کاملاً محلی است:
- فایل تک‌حجمِ وزن‌متغیر (variable font، ۱۱۱ کیلوبایت، پوشش وزن ۱۰۰ تا ۹۰۰) در
  `static/assets/fonts/vazirmatn-var.woff2` قرار دارد (از بسته‌ی رسمی npm، نسخه‌ی ۳۳.۰.۳ — دقیقاً همان
  نسخه‌ای که قبلاً از CDN گرفته می‌شد).
- `@font-face` مستقیم در `static/assets/index-AJcvwU1L.css` تعریف شده و هیچ `<link>` یا `@import` خارجی
  در `static/index.html` باقی نمانده است.
- مجوز فونت (SIL OFL) در همان پوشه (`fonts/OFL.txt`, `fonts/AUTHORS.txt`) نگه داشته شده.
- تأیید شده با بررسی خودکار: صفر درخواست شبکه به هر دامنه‌ی خارجی هنگام باز شدن برنامه.
